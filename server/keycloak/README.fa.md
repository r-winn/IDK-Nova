# تم ورود نوا برای Keycloak داخلی

این تم ظاهر ورود را با نوا هماهنگ می‌کند: روشن/تاریک بر اساس تنظیم سیستم، فارسی/انگلیسی، راست‌چین، لوگو، رنگ برند، فیلدهای قابل‌دسترسی و خطاهای هماهنگ. فایل‌های CSS و تصویر محلی‌اند و به Google Fonts یا CDN نیاز ندارند. کاهش حرکت سیستم رعایت می‌شود.

**مرز امنیتی:** این تم فقط نمایشی است. از `parent=keycloak` ارث می‌برد؛ فرم ورود، نام فیلدها، action URL، session tokenها، نمایش خطا، بازیابی و مراحل OTP/WebAuthn همچنان توسط قالب‌ها و منطق اصلی Keycloak ارائه می‌شوند. فقط footer نمایشی اضافه شده است. فعال‌بودن MFA یا بازیابی به سیاست realm/AD بستگی دارد؛ تم قابلیت امنیتی جدید فعال نمی‌کند.

## نصب در Keycloak موجود

1. پوشهٔ `keycloak/themes/nova` این بسته را در مسیر پایدار مدیریت‌شده توسط IT کپی کنید؛ برای مثال `/opt/company-keycloak/themes/nova`.
2. آن را روی کانتینر Keycloak، فقط‌خواندنی، در `/opt/keycloak/themes/nova` mount کنید. این mount مربوط به **سرویس Keycloak** است، نه کانتینر نوا. اگر Keycloak روی سرور دیگری است، فایل‌ها باید همان‌جا قرار بگیرند.

```yaml
# بخش تکمیلی سرویس Keycloak موجود شرکت؛ فایل Compose کامل نیست.
services:
  keycloak:
    volumes:
      - /opt/company-keycloak/themes/nova:/opt/keycloak/themes/nova:ro
```

3. در Admin Console، realm کاربران شرکت را انتخاب کنید؛ سپس **Realm Settings → Themes → Login theme = nova** را ذخیره کنید. realm مدیریتی `master` را تغییر ندهید.
4. در Realm Settings، `Display name` را نام نوا/شرکت بگذارید. اگر قبلاً `Display name HTML` سفارشی دارید، آن را هم بررسی کنید تا نام قدیمی نشان داده نشود.
5. برای فارسی، Internationalization را فعال کنید، `fa` و `en` را به زبان‌های پشتیبانی‌شده اضافه کنید و زبان پیش‌فرض را مطابق سیاست شرکت انتخاب کنید.
6. پس از تعویض فایل‌ها، Keycloak را طبق فرایند نگه‌داری شرکت restart کنید یا cache تم را طبق مستندات همان نسخه نوسازی کنید. cache را در تولید به‌طور دائمی غیرفعال نگذارید.

قالب پایهٔ کلاسیک `keycloak` در نسخهٔ آزمایش‌شدهٔ 26.8.1 استفاده می‌شود، نه `keycloak.v2`. بعد از هر ارتقای عمدهٔ Keycloak، ورود، خطا، OTP، بازیابی، موبایل و زبان‌ها را دوباره بررسی کنید. نصب خودکار Keycloak/AD جزو این بسته نیست. AD FS تم Keycloak را مصرف نمی‌کند؛ اگر شرکت مستقیماً AD FS دارد، برندینگ آن باید با ابزار همان سرویس انجام شود.

## هماهنگی با کانفیگ برند نوا

روی ماشینی که Node.js دارد، در یک کپی قابل‌نوشتن از پوشهٔ `keycloak` اجرا کنید:

```sh
node sync-brand.mjs /opt/idk-nova/config/config.json
```

این ابزار فقط `ui.branding` را می‌خواند و رنگ، لوگوی PNG/JPEG/WebP و کنتراست دکمه را آماده می‌کند؛ API Key یا Client Secret صادر نمی‌کند. فایل `realm-branding.patch.json` فقط پیشنهاد دو تنظیم `displayName` و `loginTheme` است؛ import کامل realm نیست و خودکار روی سرور اعمال نمی‌شود. IT باید تنظیم‌ها را روی realm درست بررسی و اعمال کند. خروجی CSS/تصویر را در مسیر پایدار تم کپی کنید. تغییر کانفیگ نوا به‌تنهایی تمِ سرویس جداگانهٔ Keycloak را تغییر نمی‌دهد.

در صورت نبودن لوگوی سفارشی، لوگوی نوا استفاده می‌شود. رنگ باید `#RRGGBB` و لوگو data URL محلی مجاز حداکثر ۲ MB باشد؛ SVG/URL خارجی توسط ابزار صادر نمی‌شود. اگر لوگوی شرکت را مستقیم جایگزین `resources/img/logo.png` می‌کنید، PNG مناسب روشن و تاریک آماده کنید. از `Display name HTML` حاوی کد نامطمئن استفاده نکنید.

## پیش‌نمایش روی مک، بدون AD و Docker

از ریشهٔ سورس:

```sh
npm run login:preview
```

یا در پوشهٔ `keycloak` استخراج‌شده:

```sh
node preview.mjs
```

سپس `http://127.0.0.1:1435` را باز کنید. می‌توانید فارسی/انگلیسی، روشن/تاریک و حالت خطا را ببینید. این صفحه از CSS و لوگوی همان تم استفاده می‌کند ولی markup آن نمونهٔ نمایشی است؛ اثبات اتصال AD یا تصویر پیکسلی تمام نسخه‌های Keycloak نیست. هیچ رمزی وارد نکنید؛ فیلدها فقط‌خواندنی‌اند، submit واقعی وجود ندارد و سرور درخواست‌های POST را رد می‌کند.

تست CI، همین تم را روی Keycloak واقعی آزمایشی نصب می‌کند و رندر فرم‌های فارسی/انگلیسی و بارگذاری CSS را بررسی می‌کند. کاربران و AD واقعی شرکت هنوز باید توسط IT تست شوند. تم تست را با محیط تولید اشتباه نگیرید.

مرجع: [مستندات رسمی تم‌های Keycloak](https://www.keycloak.org/ui-customization/themes).
