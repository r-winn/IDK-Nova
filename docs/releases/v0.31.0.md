# IDK Nova 0.31.0 — Company Linux server

## Downloads

- **Linux/company hosting:** `IDK-Nova-Server-0.31.0.tar.gz` plus its `.sha256` checksum. This is the web deployment bundle, not a desktop Linux installer.
- **Windows:** Setup.exe / MSI.
- **macOS:** Universal DMG.

## Server package

The unchanged Nova web interface can now be hosted at a company domain on Linux x86_64 or ARM64 using Docker Compose. The package includes the compiled website, Node.js gateway, locked dependencies, Caddy TLS configuration, separate company configuration examples, install/update/rollback scripts and Persian/English IT documentation.

Mandatory OIDC sign-in supports a configured Entra ID, AD FS or Keycloak issuer. Internal Active Directory can be federated by IT through Keycloak/LDAPS; Nova does not collect domain passwords. Company provider keys stay on the server. The gateway enforces configured model allowlists and request limits, validates OIDC tokens with PKCE/state/nonce, and forwards live streaming responses without reverse-proxy buffering.

Browser settings, history and attachment database names are scoped to the authenticated subject. Existing desktop and standalone static-site storage keys remain unchanged. A stale tab cannot send a company-provider request under a different account after another tab signs in.

Updates download a specified official release, check SHA-256 and archive paths, preserve external configuration, wait for deployment health and restore the previous deployment on startup failure. An explicit administrator action is required; there is no silent remote code update from the website.

## Verification and limitations

Tests cover a local OIDC issuer with signed ID tokens and PKCE exchange; state/nonce/group rejection; account isolation; same-origin checks; model allowlisting; secret/header filtering; streaming; body/concurrency limits; traversal rejection; logout; and deployment script update/checksum/rollback behavior with simulated Docker/download commands. Existing UI/agent/Office regression tests and a production UI build also run. The release job builds the actual packaged Linux container and validates Compose on Ubuntu.

The company's real AD tenant, DNS, TLS certificate, provider and user load require IT acceptance testing. This release is not a cross-device history sync service, shared session cluster, DLP enforcement system, or server-side desktop agent. Desktop-only Work/local GGUF/system-control capabilities remain disabled on the website. Histories remain in browser storage; server session memory resets on restart. A security review is recommended before company-wide deployment.
