# Nova 0.29.2 · Local GGUF connectivity

The desktop HTTP scope omitted the non-default Ollama port. Requests were rejected inside Nova before reaching Ollama. Explicit loopback entries now allow 127.0.0.1 and localhost on port 11434, including chat and model metadata paths; other local ports are not opened by this fix.

Import validates the GGUF magic/version and bounded metadata before copying. Known image/video architectures such as FLUX are rejected as chat imports using their actual architecture metadata, not guessed filenames. Unknown architectures remain subject to Ollama compatibility checks. This importer supports conversational models, not a local image-generation runtime. Model tests also detect already-imported image architectures through Ollama's actual /api/show response.

Ollama import/start/list/show commands use the same loopback host as Nova's provider instead of inheriting a potentially different OLLAMA_HOST. Registration alone is no longer announced as readiness: only the live completion test marks a model ready. Failed live tests retain the registered model with an actionable offline diagnostic, rather than implying successful inference.

Verification: production build, 78 frontend tests and 9 native tests. Native regression tests run Tauri's actual URLPattern matching semantics against the configured capability, verify port 11434 passes and another port fails, and inspect valid/truncated GGUF metadata. Frontend tests reject existing image models before inference and let compatible metadata continue to chat. A real local Qwen3-4B GGUF served by Ollama returned OK through /v1/chat/completions. A new physical installer and a complete re-import of the user's multi-GB file have not been tested locally. No existing user model files were deleted.

Sources: https://docs.ollama.com/import and the FLUX author's model card https://huggingface.co/black-forest-labs/FLUX.1-dev .
