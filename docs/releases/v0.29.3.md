# Nova 0.29.3 · Local model components

Settings → Models → Add new model → Import a local file now has separate selectors for the main GGUF and its optional matching Vision projector. Choose both before pressing Import & test. Text-only models need only the main file; monolithic multimodal models may include Vision internally. A standalone mmproj must come from the exact same model family/version, not merely have a similar filename.

Nova stores both components in a separate private import directory without changing originals or overwriting older private copies. Byte progress is aggregated across both files. The Modelfile registers the projector as another FROM model layer, not as a LoRA ADAPTER. Ollama recognizes and combines the layers; Nova does not patch Ollama manifests by hand. Use a current Ollama version supporting the selected combination.

After registration, Nova reads /api/show capabilities. If a selected projector does not enable Vision, import reports VISION_NOT_ENABLED instead of inventing a Vision badge. Confirmed Chat/Vision/Tools/Thinking capabilities are displayed in the model list. Readiness requires a live completion; Vision models are probed with a real, checksum-verified 32×32 PNG. This tests acceptance of image input, not visual reasoning accuracy or tool-call quality.

Native registration reads bounded progress chunks rather than waiting forever for a carriage return, bounds stderr storage/queue memory and stops its CLI subprocess after 30 minutes. This is an import safeguard, not a Work turn budget. Incomplete private file copies are cleaned up; originals and prior import copies are preserved. Simultaneous imports are prevented.

Scope: GGUF conversational models supported by Ollama, with optional matching GGUF projector. This does not add local FLUX image generation, audio/realtime support to text models, automatic downloads of unknown projectors or arbitrary architecture support. Incompatible pairs can still fail engine initialization and are reported rather than declared ready. Registered Ollama models may remain after a failed verification; Nova does not destructively delete them.

Verification: production build, 79 frontend tests and 11 native tests, plus browser inspection of the dark-theme import wizard. Tests cover dual FROM registration, missing Vision rejection, actual image request construction and valid PNG checksums. No successful end-to-end inference of the user's specific Qwen3.5 + mmproj pair is claimed: that pairing must pass the installed Ollama's live test on the user's device.

Primary implementation references: https://github.com/ollama/ollama/blob/main/parser/parser.go and https://github.com/ollama/ollama/blob/main/server/create.go .
