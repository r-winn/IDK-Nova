# Nova 0.30.2 — Ollama tool-continuation compatibility

## Root cause

The installed local Ollama 0.40.2 Responses compatibility endpoint returned the exact reported `500 / Jinja Exception: No user query found in messages` when given a tool output with `previous_response_id` but no user message. Nova had assumed that the endpoint stored and replayed server-side response history. This was a compatibility issue, not a failed connection or evidence that PowerPoint was unsupported.

## Fix

- For the standard loopback Ollama endpoint on port 11434, both ordinary chat and agent requests use Responses with `store:false`, no `previous_response_id`, and a full conversation transcript.
- Every agent continuation includes the original messages, returned response output items and actual tool results. Vision/screen inputs remain in the transcript.
- Other compatible providers keep their existing stored Responses behavior. A specific lost-history/template error negotiates stateless replay once; the replay log retains already-executed tool outputs instead of restarting the task and rerunning side effects. Persistent template errors fail explicitly instead of retrying indefinitely.
- Error messages no longer claim every response failure is a network outage. Jinja errors have a dedicated template diagnostic.

This follows the distinction between client-managed input history and server-managed response chains in [official OpenAI conversation-state documentation](https://developers.openai.com/api/docs/guides/conversation-state).

## Verification

Regression tests cover ordinary Ollama history, local multi-step tool transcripts, adaptive proxy recovery, exactly-once local tool execution and bounded failure. `scripts/local-agent-smoke.mjs` sends only synthetic diagnostic data to local Ollama and validates two-step execution. The `--powerpoint` mode uses the real Office schema and generator in memory, checks an actual PPTX package and then verifies the final model continuation. Diagnostic runs request reasoning effort `none`; they are transport/file-generation tests, not a benchmark or a guarantee of content quality for every prompt.

Provider/model templates can still have other incompatibilities. Biography requests must not fabricate personal information beyond facts supplied by the user. The website and desktop apps share this compatibility fix.
