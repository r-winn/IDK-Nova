# IDK Nova Server 0.31.0

Dedicated **Linux/company web hosting package**, built and tested on Ubuntu. This release does not replace the Windows/macOS desktop installer channel.

## Download for IT

Download both **IDK-Nova-Server-0.31.0.tar.gz** and **IDK-Nova-Server-0.31.0.tar.gz.sha256** below. Verify the checksum, extract the archive and read **README.fa.md** (Persian) or **README.md** (English) inside it.

The archive includes the compiled Nova website, Docker Compose deployment, HTTPS gateway, OIDC authentication, server-side company-provider proxy, configuration examples and versioned update/rollback scripts. It contains no company credentials. Source-code ZIP/TAR links generated by GitHub are not the deployment bundle.

## Company setup

- Keep the same Nova web interface; company branding/theme/models are configured in a separate JSON file.
- Use Entra ID / AD FS OIDC, or an IT-managed Keycloak connection to internal AD over LDAPS. Nova does not receive employee domain passwords.
- Register `https://YOUR-DOMAIN/auth/callback` as the confidential web client's redirect URI. Put client/provider secrets only in the server's `.env` file.
- Install with Docker Compose on Linux x86_64 or ARM64. A public DNS name and ports 80/443 allow automatic HTTPS; private PKI needs IT configuration.
- Future full Nova releases include the server bundle too. The installed manager checks the official release channel and updates to an explicit version while preserving configuration; startup failure restores the previous deployment.

## Verified

101 UI/agent regression tests and 11 server/deployment tests passed. GitHub CI built the real packaged Linux image, reran OIDC/proxy tests inside it, and validated Compose configuration. A local compiled-UI test completed sign-in, streaming chat and history restoration.

Company-specific AD, DNS/TLS and real-provider load testing must still be completed by IT. Histories stay in account-scoped browser storage, not synchronized between devices. Web-only restrictions on native Work, local GGUF and system control remain unchanged. This is a single-instance deployment, not a distributed enterprise session service.
