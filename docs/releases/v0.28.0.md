# Nova 0.28.0 · Office studio and Chrome for Work

## Real Office files, not placeholder tools

- PowerPoint studio creates editable widescreen PPTX slides with a consistent color/font theme, RTL support, page numbers and speaker notes.
- Word studio adds headings, tables with repeated header rows, page breaks, headers/footers, page numbering, font sizes, paragraph emphasis and landscape layout.
- Office plugins inspect attached DOCX, XLSX and PPTX files. Precise edits use the returned text-run/cell IDs and expected original content, preventing guessed or stale replacements. Revised files have a new filename; originals stay available. Other XML parts, graphics and styles are retained instead of flattening documents into plain text.

Install in Settings → Marketplace → Plugins. Select Word/Excel/PowerPoint beside the composer, attach a file and request a change. Alternatively use `@create_word_document`, `@create_excel_workbook`, `@create_powerpoint`, `@inspect_office_file` or `@edit_office_file`. An actual tool-calling model is required. Tools appear in the command suggestions only after installing the relevant plugin.

Scope: unencrypted DOCX/XLSX/PPTX up to 10 MB. Macro-containing archives, older Office formats and unsafe paths are rejected. Inspection results are limited to 1,000 entries/60,000 characters and explicitly report truncation. Exact edits modify existing text runs or cells, not arbitrary charts, graphics or slide arrangement. For structural changes, generate a new document/deck from inspected content. Spreadsheet formulas are not calculated by Nova; Excel recalculates when opening a revised workbook. Microsoft Office does not need to be installed, and controlling its desktop applications is not claimed.

File parsing and generation happen on-device. Binary file payloads are removed from model tool results; inspected text can be sent to the selected provider. Config export includes installed pack selections/instructions, not attached files, Chrome profiles or credentials by default.

## Native Chrome integration

Chrome for Work starts the installed Google Chrome with a separate profile per desktop Work, a loopback DevTools connection and no browser-security bypass flags. It supports opening URLs, reading visible page text/control selectors, clicking and filling ordinary text inputs. The existing Ask / Approve for me / Full access policy applies; local-only Work disables it. It does not attach to your personal Chrome profile or export browser sessions.

For login passwords, CAPTCHA, OTP, payment and consequential submissions the agent is instructed to hand control to the user. Password/file/hidden input filling is rejected by the native handler. This integration is not a promise of arbitrary website compatibility, iframe control, visual-pointer automation or a complete multi-tab browser suite. Chrome must already be installed. Closing Nova closes only Chrome processes started by this plugin.

Profile isolation follows [Chrome's remote-debugging guidance](https://developer.chrome.com/blog/remote-debugging-port?hl=en). The default Nova internal browser remains the usual Work route unless this plugin is explicitly selected.

## Better instructions and clear progress

- Article workshop: `@write_article`, `@edit_article`.
- Academic research: `@literature_review`, `@research_proposal`.
- Business communication: `@decision_brief`, `@pitch_deck`.
- Spreadsheet analysis: `@audit_dataset`, `@spreadsheet_report`.

These packs supply editorial structure, evidence rules, methods, constraints and revision checks. They cannot grant tools or make unsupported providers perform research. Streaming remains the default when the provider supports it.

Ordinary and temporary side chats show real observable stages: waiting for the model, inspecting files, creating an Office output and writing the response. No fabricated model-thought stages or completion percentages are shown. Optional tool arguments remain optional across Responses providers using explicit `strict: false` with runtime validation, following [OpenAI function-calling documentation](https://developers.openai.com/api/docs/guides/function-calling).

## Verification

73 frontend tests, production build and 6 native tests passed locally. Tests open actual DOCX/PPTX ZIP parts and reload XLSX workbooks to check styles, tables, notes, precise edits and preservation of unrelated parts. Browser UI testing created a styled Word file, inspected/edited it in the same conversation and generated a real PowerPoint attachment, without sending binary data to the test provider. New packs installed through the real Marketplace download path.

Native tests exercise DevTools request/session matching and genuine error propagation using a local WebSocket test server; release jobs run them on Windows and macOS. Physical installer, real Chrome browsing and visual rendering in Microsoft Office are not claimed as completed end-to-end tests. The JavaScript dependency audit reports no known vulnerabilities; this does not certify the whole application or every native dependency.
